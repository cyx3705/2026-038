# SolidEdgeMCP 现行约定

本文件是项目长期约定的唯一入口。项目状态、目录和验证命令以根目录 `project.manifest.json` 为准，服务行为以 `b-Code-SolidEdgeMCP` 的源码、测试和 `VALIDATION.md` 为准。

## 取舍

- MCP 接口固定为 4 个外壳工具（`se_find`/`se_call`/`se_load`/`se_unload`），具体操作是内部指令。工具列表永不变化，客户端拉一次就够，不依赖 `tools/list_changed` 通知（已实测本机客户端与 Vulcan 都没有这条通路）。
- 内部指令编译在单独的 `SolidEdgeMcp.Commands` 程序集，外壳读入内存后载入可回收上下文，运行中重建即可 `se_load` 热换；不采用运行时编译源码，换来构建期检查、无编译器依赖、无“任意代码”入口。
- 草图指令输入声明式元素，输出以读回的几何为准（结构化 JSON + 由读回几何生成的 SVG），默认不出 PNG；需要图片时用 `view_sketch png=true`。描述有缺陷时不动 CAD；画完与描述不一致就删除并报错。
- 草图的关系必须在给定几何上已经成立，尺寸值从几何量出（写了 `value` 就必须相符）；画之前在本地检查，画完逐项核对 Solid Edge 里的值。不依赖求解器去"修"几何。
- 草图编辑在描述上精确计算后整张重画，不用 Solid Edge 的就地编辑；本服务画的草图把描述存在外壳 `State`（`sketch:<profile_id>`），热换后仍可编辑。
- 新的 Solid Edge 行为先用 pywin32 在本机探测（`win32com.client.GetActiveObject`），确认参数语义后再写进指令，结论记入 `VALIDATION.md` 的适配事实。
- 外壳与指令的契约收到最小：外壳只认名称、说明、类别、参数 JSON Schema 和 `Execute(原始 JSON 参数)`。参数规格与校验、`SeCommand` 基类、内核操作都在指令工程 `Kit/`，可热换；外壳不再为参数或 CAD 逻辑的变化重新发布。
- 指令需要数组/对象参数时用 `ToolParameter.Structured` 附完整 Schema，`Read` 只校验顶层类型，内部由指令自己校验。
- 每条指令有开关：代码给默认值，运行时切换写入本机 `config/commands.json`。关掉的指令在嵌套调用里同样不可用。
- 跨热换必须保留的状态（COM 连接、文档 ID、轮廓）只放在外壳 `SolidEdgeBackend`；新指令需要的新状态放进其 `State` 字典，只存框架、外壳或 COM 类型的对象；指令类不得持有静态状态。
- Solid Edge COM 对象全部留在单一 STA 工作线程，避免跨线程代理导致的随机 COM 错误。
- 文件写入限定在项目输出根目录，已有文件必须显式 `overwrite=true`，避免 AI 静默覆盖用户文件。
- 建模写入后读取体积、尺寸或回读参数确认结果。COM 没有事务回滚，超时或异常后先查询模型再决定下一步。
- 第一版只覆盖有序单实体零件。装配、工程图、钣金和同步建模属于后续范围。

## 工程约定

- 根目录可见文件夹只有 `a-*`、`b-*`、`z-*`；新增目录登记进 manifest 的活动目录。
- 不直接编辑生成的虚拟环境、配置、数据和构建目录；它们位于 manifest 的 generatedRoots/contextExclusions。
- 所有构建、测试、合同检查和实机验收命令登记在 manifest 中。
- 不提交、推送、发布或把本机密钥、令牌和机器状态写入仓库。
- 第三方参考项目、提交号和许可记录在 `b-Code-SolidEdgeMCP/THIRD_PARTY_NOTICES.md`。
